# EDINET Research Foundation

日本企業の開示・市場・文章・人的資本・企業間関係を、出所と時点を失わず研究するための初期基盤。

**現在の状態：設計仕様、安全性カーネル、P0–P1の最小取得・監査処理。統合済みの実データセットではありません。**
候補アーカイブの2022年公開サンプル1行と、既存ローカルEDINET原本・日次一覧の照合に成功しました。
現在の公式API取得は認証不足でBLOCKEDです。ローカル原本の一致をlive取得成功とは扱いません。
全市場カバレッジ監査、公開権利の承認、運用バックテストは未実施です。
既存研究の結果・非公開の記録・J-Quants取得データは同梱しません。

実行方法・確認範囲・制約は [P0–P1実装記録](docs/P0_P1.md) を参照してください。
ローカル原本の難例・確率標本を分けた限定監査は [P2受入監査](docs/P2.md) を参照してください。
P2で残った102件のmetadata欠損の調査結果は [metadata欠損監査](docs/METADATA_GAPS.md) に記録しています。

## ローカル検査

Python 3.11以上。安全性カーネルは標準ライブラリのみです。

```sh
python -m unittest discover -s tests -v
python -m compileall -q evidence_core.py tests
```

テスト用の数値・企業IDはすべて明示的な合成データです。テスト成功は、実データの正確性や投資成績を意味しません。
`evidence_core.py`は保守的な日時選択、欠損・訂正の取扱い、累計差分の比較可能性、学習ラベルの成熟、負の分散の拒否を実装します。宣言されたメタデータを検査するもので、出所の真実性を自動証明するものではありません。

## 設計の原則

数値の多さより、原本→抽出→標準化→特徴量→予測→評価の追跡可能性を重視します。
直接報告、計算による派生、代理指標、補完、モデル予測、過去の報告値、合成テストデータを区別します。
公開当時の情報を今から再構築した結果と、当時そのシステムで取得していた情報の再現を分けます。
探索・確認・予測・因果推論を混同せず、失敗した仮説と試行数も保存します。

## Codexへの最初の依頼

```text
AGENTS.md、docs/ARCHITECTURE.md、docs/CODEX_BACKLOG.mdを読む。
まずP0のソース受入監査とP1のraw manifest/書類マスタだけを実装する。
registry/sources.jsonの候補を実データ採用済みと扱わない。
実際にアクセスできる公開サンプルのschemaと原本を確認し、
取得日時・バイトハッシュ・上流書類ID・利用条件・欠損理由を保存する。
認証や原本が不足する経路はBLOCKEDとして記録し、架空の実測値で補わない。
自動テストを実行し、実装済み・実行済み・実データ検証済みを分けて報告する。
全市場一括取得やモデルの大量探索にはまだ進まない。
公開リポジトリへ生データ、非公開研究、認証情報を追加しない。
```

公開コードと私有データ保存先を分離してください。コードの公開はデータの再配布許可を意味しません。
