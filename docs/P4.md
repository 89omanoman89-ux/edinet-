# P4: 既存ローカル市場データとの保守的PIT結合

P3の固定primary 35書類とrevision_support 14書類だけを使用する。
P0–P3の実装、P2標本、原本、過去snapshotを変更しない。対象を成功した書類に入れ替えない。
今回のP4はデータ結合と検証に限定し、backlogにあるリターンラベル・コスト・評価は実装しない。
P5、バックテスト、ランキング、仮説探索、全市場展開は対象外。

## 実装と採用条件

- `jquants_local.py`: Git外の既存CSV/GZIPと保存済みmanifestをread-onlyで検査する。各datasetでrevisionが複数あれば任意に最新版を選ばず拒否する。
- `pit_market.py`: 時点付き証券mapping、日次session、価格の公開時刻、P3 `as_of`を検査するカーネル。
- `p4_audit.py`: P3固定標本を起点に対象ファイルを先に固定し、新規の私有snapshotへ監査結果を保存する。
- `registry/p4_contract_v1.json`: 時点・価格basis・識別子・比較の定義版と参照仕様。

entity、filer/issuer/subject、security、code、有効期間、上場期間、提供者の行、取引sessionを分ける。
codeは4/5文字の文字列で、英字・先頭ゼロを保持する。名前join、末尾切捨て、補完は禁止。
日付付きmaster行とEDINET提出metadataのcodeが等しくても、issuer関係や有効期間の証明へ自動昇格しない。
複数候補、期限不明、上場境界不明、判断時点以降にしか利用できないmappingはBLOCKED。
code変更・再利用時には価格観測日にも同じsecurityとの対応が有効でなければ採用しない。

正のカーネル入力には、明示的に検証された有効期間・上場期間・issuer関係・公開時刻と、
hash/行locator付きmapping証跡が必要。証跡の書式検査だけで主張の真実性を認証するものではない。
P3原本逆引き済みfact IDと、J-Quantsバイト・CSV行再読済みobservation IDも別々に要求する。
現在のローカルCSV用adapterは、この追加証跡がない候補をBLOCKEDのまま出力する。
任意の自己申告JSONをPASSのmappingとして取り込むCLIは設けていない。

## 時間と価格

監査のdecisionは各書類のP3公開時刻上限の1 microsecond後。P3の訂正系列・競合・nullをそのまま使う。
calendarに全日付が存在することを確認し、公開時刻とdecisionより厳密に後に始まる最初の**日次barのsession**を候補とする。
日次データだけなので、場中・引け後開示は次の取引日の開始へ進む。午前開示に同日午後の価格を割り当てない。
休日とOSEだけの祝日取引日は東証現物のsessionとしない。欠落日を平日規則で生成しない。
半日取引の時間が未確認ならBLOCKED。session予定と実際の約定を区別し、`execution_claim=false`とする。

正のjoinには、entry候補時点の売買可否を判断時点までに確認した証跡も要求する。
売買停止・売買可否不明・上場廃止・価格なしを黙って除外して次の好都合な価格へ進まない。
価格featureは判断日の前日以前の、対象codeで最新の報告終値だけを候補とする。
観測日を保持し、当日終値や未来のentry価格をfeatureへ入れない。公開時刻が不明なら採用しない。

非調整価格と元の`AdjFactor`/`ExRT`を別々に保持する。将来の分割を過去価格へ反映しない。
調整済み価格の版が不明、または判断時点以降なら拒否する。既知版の調整済み価格も今回の採用範囲外。
価格×株数、配当込みreturn、CFO-CapEx等を作らない。EPS/BPS/株数の調整basisが未確認なら定義差として残す。

## 独立した財務sourceの比較

J-QuantsのFY実績だけを、小さな明示的field定義で比較候補にする。予想・四半期・未確認定義は台帳へ残す。
期間、flow/instant、scope、会計基準、unit、share basis、公開時刻、訂正を照合する。
IFRSのEq/BPS等は意味を推測してP3 metricへ割り当てない。EDINET訂正はrevision_differenceを保持する。
分類はexact_match / timing_difference / definition_difference / scope_difference /
accounting_standard_difference / revision_difference / value_conflict / unresolved。
identity未確認なら数値一致を認証しない。時刻適格性とidentity適格性を別々に記録する。
J-Quantsの報告時刻はCSV内の開示時刻であり、保存済み版の当時の配信・取得成功とは扱わない。
独立sourceのIDを維持し、P3のBLOCKED・unknown mapping・訂正nullをJ-Quantsで埋めない。

## 私有実行と成果物

```sh
python p4_audit.py --jquants-root /absolute/private/jquants --edinet-local-root /absolute/private/edinet --p3-snapshot /absolute/private/p3/frozen-snapshot --private-dir /absolute/private/p4 --snapshot new-unique-snapshot
python -m unittest discover -s tests -v
```

新規API取得、secret、networkは不要。入力を含むGit checkout、入力配下への出力、既存snapshotの上書きを拒否する。
master/価格は各提出日−10〜＋14暦日、財務比較は−370〜＋14暦日で先に固定する。
対象月ファイルをバイト検査・schema/件数再計測し、私有出力には固定対象codeと期間の行だけを保存する。
calendarは利用可能な1ファイルを検査する。未選択ファイルのmanifest記載は主張であり実測と区別する。
全成果物にsnapshot ID、コードbundle SHA、定義版、synthetic、rights状態を付ける。

原本、J-Quants個票、実doc_id、私有絶対pathは公開Gitに含めない。rights BLOCKED、export_allowed=falseを維持する。

## 公式仕様との対応

- [master](https://jpx-jquants.com/en/spec/eq-master): 日付付き観測。名前一致をissuer証明に使わない。
- [日足](https://jpx-jquants.com/ja/spec/eq-bars-daily) / [bulk調整](https://jpx-jquants.com/ja/spec/eq-bars-daily/adj): bulkの非調整価格と調整係数を分離。NULL価格だけでは売買停止理由を特定できない。
- [calendar](https://jpx-jquants.com/ja/spec/mkt-cal) / [休日区分](https://jpx-jquants.com/ja/spec/mkt-cal/holiday-division): 日付と区分を観測し、時刻を捏造しない。
- [財務](https://jpx-jquants.com/ja/spec/fin-summary) / [書類種別](https://jpx-jquants.com/ja/spec/fin-summary/typeofdocument): 開示日/時刻・元field・決算期・scopeを維持。
- [東証取引時間](https://www.jpx.co.jp/equities/trading/domestic/01.html) / [2024年延長](https://www.jpx.co.jp/corporate/news/news-releases/1030/20230920-01.html): 2016年以降の全日開始09:00、2024-11-05から終了15:30、それ以前15:00という限定rule。予定sessionであり約定証明ではない。
