# P2: bounded local acceptance audit

P0–P1を複数書類へ適用する工学的な受入監査。財務標準化、J-Quants、成績検証、仮説探索、全市場取得は行わない。
標本の成功率を全市場の精度・エラー率へ外挿しない。`full_market_representativeness=NOT ESTABLISHED`。

## 固定する母集団と選択

母集団は、明示されたGit外のローカルarchiveに存在するZIPの重複を除いたdoc_id。
日次一覧にしかない書類数も別に記録するが、未取得ZIPをprobability母集団へ含めたと偽らない。
元ZIP・一覧・取得ログは読み取り専用。APIやsecretにはアクセスしない。
母集団manifestとdoc_id別の一覧イベントを保存してから構造確認・標本選択を開始する。

- `archive_snapshot_identifier`: ZIPの相対path・size・mtime、日次一覧の実バイトSHA-256・イベント内容から生成。
  全原本のバイトhashではない。選択書類では実ZIPのhash・長さ・mtime・任意の既存取得ログを再検査する。
- 件数、日付範囲、書類種別、EDINET code数、証券コード有無、日次一覧coverage、ZIP重複を保持する。
- seed `20260918`。順位は `SHA-256(str(seed) + ':' + doc_id), doc_id` の昇順。
  Pythonの実行依存hashやディレクトリ列挙順は使用しない。
- probability: ZIP母集団全体の固定順位の先頭15件。発行体で再重み付けしない。
- challenge: probabilityの15件を除いて20件。各categoryを満たす固定順位先頭を選び、既選択書類が
  他categoryも満たせば再利用する。第三者重複は事前に3書類を目標に確保する。
  余枠は新しい提出主体、次に固定順位で埋める。最低30の提出主体を目安とし、不足はBLOCKED。
- 構造の事前確認は最大120件。probability候補、一覧由来categoryごとに最大4件、固定順位の順で確定。
  実際のthird-party tie結果を参照して選択しない。確定後の書類は失敗しても置き換えない。
- 確率標本と難例標本は互いに重複せず、分母・結果を別々に保存する。
  合計成功率は出さない。構造確認件数と最終監査件数も区別する。
- 構造確認＋最終監査の予算合計を300以下に制限する。既存snapshotは再実行・上書き・再選択しない。

不具合修正後に別snapshotで同じ標本を再検査する場合だけ、`--frozen-selection`へ以前の
`selected_documents.json`を指定できる。全母集団のZIP記述・一覧イベント、seedと予算、
両標本のdoc_idと選択理由が完全一致しなければ停止する。以前の選択時刻・選択コードSHA・
選択ファイルhashを継承し、監査コードSHAとは区別する。失敗書類の差し替えには使用できない。

一覧には同じdoc_idの複数イベントを残す。照合用イベントは提出日当日の最初の連番を優先し、
ない場合は最初の観測を保持して当日のmetadata tieはBLOCKEDとする。
複数ZIP、矛盾する提出者・証券コード・提出時刻は曖昧として記録し、黙って最新へ置換しない。

## 難例の意味と未発見

JP GAAP/IFRS・連結有無はDEI、連結/単体のcontextはdimension、複数segmentはsegment dimension memberで識別する。
赤字は限定したProfitLoss系タグの負値の存在、決算期変更はDEIの非通常期間長という**候補の手掛かり**。
会計指標の標準化や決算期変更の確定判定ではない。金融/REITは明示的なDEI業種値だけを認め、社名から推測しない。
複数証券コード・名称履歴は一覧で観測した値の変化で、同時発行証券数や法的社名変更の証明ではない。
証券コードnullを非上場の確定判定に変換しない。大きいZIPは事前固定の2 MiB以上。

訂正有報、parentDocID、非通常status、英字コード、複数member、同一tagの複数context等も対象。
未発見は`not_found_in_available_archive_screen`等で保存する。構造の探索範囲は固定した120件であり、
archive全体に存在しないという主張ではない。失敗を含む構造確認結果も別ファイルへ残す。

## 書類ごとの監査と構造profile

doc_id、提出日/原提出日時、提出者/発行対象/対象会社のrole、証券コード、parent、statusを保持する。
roleを相互に推測補完しない。提出主体数と、明示的なissuer roleの識別子数を別集計にする。
ZIP hash/bytes、原本形式・parse状態、member名/hash、namespace、QName集合hash、context/unit数、
instant/duration・period、units、dimensions、segment/scenario、DEI、text block数、numeric fact数を測定する。
fact値の表や本文を公開出力しない。duplicate候補は同一member内のQName/contextRef/unitRef/lang重複であり、
別contextの同じタグや別memberの同じcontext IDを誤って重複としない。

XML宣言のDOCTYPE/ENTITYを拒否し、ZIP展開後サイズを32 MiB以下に制限する。
raw_missing、metadata_missing、byte_integrity_failed、invalid_zip、xml_rejected、xml_parse_failed、
unsupported_encoding、unknown_document_type、identifier_ambiguous、context_ambiguous、unit_unknown、
original_metadata_mismatch、third_party_mismatch、rights_unresolved等を分けて台帳へ保存する。
parse成功と意味上の曖昧さは独立で、parseできてもcontext/unit等の失敗は残す。
現在の書類type受入は120/130。他typeは保持して`unknown_document_type`を付ける。

numadはP0–P1と同じ固定commitの2022年artifact manifestを明示入力する。
利用可能な完全JSONL行のうちdoc_idごとの最初の行を固定し、ZIP内タグと正規化本文を既存比較器で照合する。
部分ファイルに存在しない場合は`third_party_overlap_not_available`。不一致や原本解析失敗とは分離する。
加工テキストとの一致はEDINET原本の正確性の証明ではない。rightsはBLOCKED、`export_allowed=false`を維持する。

## 私有出力の契約

すべて私有snapshotディレクトリ内。主成果物のJSON/JSONL各レコードには
`snapshot_id / code_sha / code_sha_kind / synthetic / export_allowed`を付ける。
`code_sha`は使用したPythonソース8ファイルのUTF-8・LF内容hash一覧をcanonical JSON化したSHA-256。
対象ファイル名と個別hashをuniverse manifestに保持し、commit以外の作業中コードも識別可能にする。

| ファイル | 内容 |
|---|---|
| universe_manifest.json / universe_documents.jsonl | 選択前の母集団と元イベント、入力版、seed・予算・選択時刻 |
| screen_plan.json / structural_screen.jsonl | 事前固定した構造確認対象と結果 |
| selected_documents.json | 両標本、難例の選択理由、未発見と不足 |
| challenge_sample.json / probability_sample.json | 個別の標本と固定選択規則 |
| document_audit.jsonl | 各書類の独立した監査状態と原本/一覧の証跡 |
| schema_profiles.jsonl | member別構造、QName hash、DEI等 |
| failure_ledger.jsonl | 書類・構造確認・inventory・選択の失敗、重複未利用はunavailable |
| coverage_summary.json / source_tie_summary.json | 標本ごとの分母と件数、外挿禁止 |
| third_party_input.json | 版固定manifest、完全行の範囲と重複範囲の制約 |

P0–P1 adapterの不変local manifest/checkpointも同じ私有ディレクトリへ保存し、主成果物から参照する。
Gitへ追加するのはコード、合成テスト、この説明と高水準の件数のみ。

```sh
python -m unittest discover -s tests -v
python p2_audit.py --edinet-local-root /absolute/private/edinet --private-dir /absolute/private/p2 --snapshot p2-acceptance-v1 --seed 20260918 --numad-manifest /absolute/private/numad/manifests/manifest-hash.json
```

`--numad-manifest`がない場合も原本の構造監査は可能だが、第三者重複は利用不能として残す。
GitHub Actionsは既存のoffline unit testsのみ。実原本、実secret、外部通信をCIへ渡さない。
