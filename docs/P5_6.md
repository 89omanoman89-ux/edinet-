# P5.6 — private coverage inventory

この段階は既存privateファイルの棚卸しと、事前固定した年跨ぎ標本の受入検証である。
2016〜2026は11暦年の区分であり、10年分の全市場データが存在するという主張ではない。
README、release全体の行数、Parquet footerの行数を取得済みcoverageへ転用しない。

## 実行

private JSON planで`roots`を明示する。各rootは`id / source / kind / path`を持ち、
`kind`は`edinet / jquants / derived_bundle / snapshots / package`。
`snapshots`の`accepted_snapshot`は、過去の失敗版を現在の合格状態へ昇格させないための固定指定。
planには対象外rootも記載する。ディスク全体・Drive・提供者全体の完全性は主張しない。
入力rootの重複、Git内のroot、入出力rootの包含関係、既存出力snapshotを拒否する。

```console
python coverage_inventory.py --plan /PRIVATE/plan.json --output /PRIVATE/new-inventory
python coverage_replay.py --inventory /PRIVATE/new-inventory --output /PRIVATE/new-cross-year
python coverage_replay.py --inventory /PRIVATE/new-inventory --verify-partition PARTITION_ID
python -m unittest discover -s tests -v
```

実データのParquet検査には既存の`requirements-p5-audit.lock`のruntimeを使用する。
公開CIは従来どおりstdlibの合成テストだけを実行し、private root・secret・networkを使用しない。

## 成果物と数え方

全てGit外。snapshot ID、観測時刻、コードSHA、rights BLOCKED、export falseを保持する。

| 成果物 | 内容 |
|---|---|
| inventory_plan.json | 明示root、コードhash、対象年、選択規則、除外範囲 |
| source_files.jsonl | 実ファイルのSHA-256、bytes、mtime、実際にdecodeした行数または理由付きnull |
| date_coverage.jsonl | source/table/日付の意味/month別の行・ID・日付集合・入力artifact |
| document_coverage.jsonl | exact doc_idによる原本・metadata・加工source・既存受入状態の関係 |
| overlap_matrix.jsonl | doc_id共通集合。値の一致でも独立証拠でもない |
| gap_ledger.jsonl | 欠損、未取得range、識別子曖昧、未観測partition等 |
| expansion_queue.jsonl | source/month/table、hash固定input、実測に基づくrows/bytes、dependency、状態 |
| coverage_summary.json | source別集計。研究許可・全市場代表性・system replayは別軸 |
| cross_year_selection.json | 実行前に固定した年ごとの1書類。欠損年度も残す |
| preservation_proof.json | 入力file集合・SHA・bytes・mtimeの再検査。既存CURRENTも対象 |

物理ファイル件数・物理bytesにはcheckpointやaliasも含む。論理行数では同一source/tableの
同一bytesファイルを重複加算しない。各snapshot版、tableの行数を独立観測数として合算しない。
証券コード件数は文字列コードの種類数であり、時点付きsecurity identity件数ではない。
月を跨ぐ入力ファイルのbytesは複数partitionから参照されるため、queueのbytesを単純合算しない。

日付軸は提出日、J-Quants Date/DiscDate、原本metadataからの明示的な日付参照、
providerのperiod_end等を区別する。日付がない行はunknownに残し、filenameから日付を創作しない。
EDINETの空の日次一覧も、その日のmetadataファイルがあるという観測として残す。
完全な提供者母集団が確認できないため、取得済み行がある月もupstream completenessはUNKNOWN。

Parquetは保存済み完全ファイルまたはhash確認済みrangeから読み取れるrow groupだけをdecodeする。
remote総行数はclaimのまま保存する。JSONL prefixの最後の不完全行は数えない。
欠けたrangeをネットワークで補充しない。

## 状態

`data exists / source tied / canonical eligible / PIT eligible / research ready`を分離する。
原本ZIPのファイル名・doc_id一致だけではsource tieにしない。
既存P3のsource-tied fact、固定したP3のlatest-restated view、固定P4のPASS行は、
それぞれの既存snapshotに限定した観測として記録する。新規書類へ状態をコピーしない。
rightsはBLOCKEDのまま、研究利用可否をcoverage件数から推測しない。
固定した既存P5の照合結果も、現在存在する原本SHAと一致する比較行数として別記する。
今回追加でdecodeした行へ、過去の少数標本の受入状態を広げない。

queueのREADYは**hash固定されたローカル入力を列挙・検証できる**という意味。
後続の原本検査・revision closure・PIT・source受入・rightsの合格を約束しない。
BLOCKEDは既知の入力欠損や対象外書類、UNKNOWNは将来月や未確定の後続依存。
COMPLETEは状態語彙として予約し、未実施の全量処理に付与しない。
`--verify-partition`はREADYでも入力bytesを再検査し、変更があれば実行を拒否する。

次PRで原本partitionを展開する場合は、`--p3-partition PARTITION_ID --output /PRIVATE/new-batch --limit 1`
で固定順序のbounded batchを実行できる。今回この全量展開経路は実データでは実行しない。
既存resultはcheckpointとして再利用し、失敗・中断を成功書類へ交換しない。
P4/P5/P5.5への全量展開は追加依存がUNKNOWNのままで、P3 READYから自動昇格しない。
hash checkpointを再利用する場合も、保存証明の完成前に全入力を再hashする。

## 年跨ぎ検証

原本ZIPが存在する書類種別120について、年ごとに
`SHA256(JSON [固定seed, year, doc_id]), doc_id`の最小値を選ぶ。
canonical/PIT/source tieの結果は選択に使用しない。選択後の失敗で書類を交換しない。
年度内に候補がなければBLOCKEDとして残す。

元P2標本は変更せず、新しいprivate frameを作る。P3は同一archive内のrevision closureを
既存コードで検査する。別archiveの全訂正を把握したと解釈しない。
P4は既存のdirect-dated規則、P5は既に保存されたbytes、P5.5は新規専用rootを使う。
日次一覧は`documents.json`、`list_YYYY-MM-DD.json`等を認識し、manifestを除外する。
原本が複数rootにある場合、固定済み日次file件数が最大のroot、root ID、pathの順で選ぶ。
新しいprivate `archive-view`へ、固定rootの日次一覧全件と、対象書類および
既存`revision_series.inventory_series`が返した訂正閉包の原本・取得記録をコピーする。
無関係なZIPの再走査を省き、root直下の保存形式も既存P3の構造へ適応する。
`origin_map.json`で元root/path/hashと閉包を保持し、元ファイルの名前・bytes・mtimeを変えない。
既存のP5.5 CURRENTは書き換えない。P5の入力欠損を他の加工値で埋めない。

処理が完走したこと、非null canonicalがあること、PIT PASS行があること、
各派生sourceとの原本照合、package検証、研究許可を別々に報告する。
P3〜P5.5の定義変更、全量財務処理、Drive upload/delete、return、P6、backtest、仮説探索は対象外。
