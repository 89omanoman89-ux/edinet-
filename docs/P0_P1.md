# Issue #1: P0–P1 minimal acquisition

対象は公式EDINETの日次書類メタデータ1日分と、numad候補の2022年JSONL先頭1行。
正の照合候補は固定commit `e1dd7e00d5de82aa1b00cf7a28c829d327a93ca7` の
`yuho-2022.jsonl`、固定locator `jsonl:line:1`。2014年は歴史アーカイブの負の経路専用。
候補registryは採用認証へ変更しない。P2以降、全市場取得、成績検証は対象外。
標準ライブラリのみで追加依存なし。単一ローカルwriterを前提とする。

### ローカル原本の扱い

```sh
python sample_audit.py --private-dir ../edinet-private/issue-1-followup --snapshot p0-p1-2022-20260918 --sample-year 2022 --edinet-date 2022-01-31 --edinet-local-root /absolute/path/to/local/edinet --verify-resume
```

`--edinet-local-root`は絶対pathかつGit checkout外。入力root内への監査出力も作成前に拒否する。
`local_edinet.py`はファイルをread-onlyで開き、改名・書換え・ZIP展開・rawコピーを行わない。
私有manifestにはrootの識別hashと相対locatorだけを記録し、絶対pathを出力しない。
観測時刻・mtime・byte hash/countは区別し、同じ内容/mtime/logの再監査は最初のmanifestを再利用する。
過去の取得時刻は一致するローカル取得ログがある場合のみ`matching_local_log_claim`として保存する。
ログがなければ`original_provider_retrieved_at=null`と欠損理由を保存し、mtimeから推測しない。
今回の実ファイルにはhash・長さ・書類IDに対応した取得ログが存在した。これも現在のAPI実行ではない。

ZIPは`documents/<doc_id>.zip`または`<doc_id>.zip`を優先し、なければ指定root内を検索する。
先頭行のZIPがなければ、固定commitの2022年JSONL全体を最大256 MiBの範囲で私有取得し、
ローカルZIPのdoc_idとの共通集合を作る。昇順先頭doc_id、そのdoc_idの最初の行を選ぶ。
file・line number・doc_id・選択規則・共通集合を保存し、本文一致の成否で別書類へ選び直さない。
今回は先頭行が存在したので全ファイル取得・共通集合生成は不要だった。

ローカルmanifestは`acquisition_method=preexisting_local_archive`、
`provenance_class=preexisting_local_official_archive`。numadは`third_party_derived`、
API経路は`live_official_api`、テスト用adapterは`synthetic_fixture`として区別する。
`local_archive.local_official_original_tied/metadata_tied`と
`routes.live_official_metadata_fetch/original_fetch/original_tied`が独立した判定。
既存`source`監査のAPI照合状態もローカル成功で上書きしない。

ZIP hash/count、member名/hash、QName、contextRef、element index、両側の生本文hashと
正規化本文hashを保存する。原本の出自は指定archiveと取得ログの主張に基づき、真正性の独立証明ではない。
対応する日次JSONがなければ`local_daily_metadata_not_available`でBLOCKED。架空の一覧は生成しない。

## 実装

- `source_acquisition.py`: HTTPSのサイズ上限付き取得、リクエスト間隔、429/5xxと通信失敗の
  bounded retry/backoff、秒数/HTTP-dateのRetry-After、完了リクエストからの再開。
  60秒超の待機要求は`retry_not_before`付きBLOCKED。再実行もその時刻まで取得しない。
- 生バイトはSHA-256名でリポジトリ外へ保存。fsyncした一時ファイルを上書きなしで公開。
  異なるバイトは別ファイル。成功manifestとcheckpointは不変。同じ完了要求の再実行は
  取得時刻を含む同じmanifestを返し、保存バイトのhash/長さも再確認する。
  中断中の未完了転送は最初から再取得する。任意byte offsetからの再開ではない。
- manifestに取得時刻、HTTP結果、safe URL、バイトhash/長さ、doc_id、提供者版、
  API仕様版、利用条件URL、欠損理由を保存。提供者の書類版が不明ならnull。
  日付・type以外のURL queryは要求時に拒否し、資格情報は明示したsecret getterから渡す。
  認証付き通信はredirect禁止。エラー本文・例外本文・任意response headerを保存しない。
- 失敗を削除せず別レコードに残す。空応答、未取得、schema不一致、権利不明は理由付きBLOCKED。
  `docs_checked / file_fetched / schema_profiled / source_tied / rights_reviewed`は独立する。
  docsはレビュー済みバイトhashとの一致が必要。ダウンロードだけではdocs確認へ昇格しない。
- `filing_catalog.py`: EDINET/numadの列型・識別子・件数の検査、元列名とnull理由の保持。
  書類snapshotは原バイトと対応を検査し、日次URL・連番ごとに追加・変更・不在差分を記録する。
  同じdocIDの複数イベントを同一行へ潰さない。
  parentDocID、取下げ、書類情報修正、開示状態を元のまま残し、不在だけから取下げを推定しない。
  同一内容への復帰も新しい取得snapshotとして履歴化する。
- 企業と証券は別表。識別子と名称にvalid/recordedの半開区間と出所を付ける。
  EDINET/法人番号は企業、証券コードは証券へ属する。4/5文字・英字を保持する。
  書類の提出者・発行対象・対象会社は別roleで、同一会社と推定結合しない。
  不明な有効開始日はnullでas-of照合対象外。矛盾する識別子の照合は停止する。
  マスタの保存・検査契約であり、実企業の歴史マスタを構築したという意味ではない。
- `sample_audit.py`: opt-inの実データ統合実行。固定commitから64 KiBをRange取得し、
  完結した先頭JSONL行だけをprofileする。全ファイルのhash/検証と呼ばない。
  原本照合は公式書類APIの取得済みZIPに対する書類ID・XBRLタグ・正規化本文の一致。
  URL/書類IDだけの一致や提供者同士の一致を原本照合へ昇格しない。

## 実行

```sh
python -m unittest discover -s tests -v
python sample_audit.py --private-dir ../edinet-private/issue-1-followup --snapshot p0-p1-2022-20260918 --sample-year 2022 --edinet-date 2022-01-31 --edinet-secret-env EDINET_API_KEY --verify-resume
```

`--private-dir`はGitリポジトリの外で、私有権限を設定した保存先を指定する。
スクリプトはOSのACLを変更しない。既存Git checkout配下・repository内・解決後のpath escapeを拒否する。
raw、manifest、監査、schema、書類・マスタsnapshot、失敗履歴はすべてここへ保存する。

認証の既定は無効。公式メタデータ/原本経路は`approved_secret_not_configured`を保存する。
ユーザーが承認したsecret管理から環境へ供給済みの場合に限り、設定**名**を
`--edinet-secret-env EDINET_API_KEY`として指定する。値を引数やチャットへ渡さない。
既存`.env`や他の研究領域から探索・転用しない。公開CIでは実行しない。

同じsnapshotは取得済みバイトを再利用する。可変な日次応答や規約を再観測するときは
新しい`--snapshot`を指定する。過去snapshotは上書きしない。候補の変更は別のP0レビューが必要。

`--verify-resume`は同じ引数で2回実行し、raw・manifest・checkpointのバイトhashとファイル集合、
2回目のcache hit数・network attempt数を私有`resume_checks/`へ保存する。
成功済みartifactだけが検査対象で、認証BLOCKEDの公式ZIPを検査したことにはしない。
失敗の再試行時刻を含む監査レコードは新しく追記されるが、成功manifestは変更しない。

## 保持期間と正の照合

公式仕様書1-2-2（印刷頁5）の有価証券報告書の閲覧期間は原則10年で、休日による延長がある。
提出日の10年後から31日以内は境界の確認待ち、31日超なら
`outside_official_retention_window`として原本要求を停止する保守的な事前判定を使う。
これは保存した提供者の提出日とレビュー済み仕様に基づく経路判定で、HTTP応答や正確な削除日時の実測ではない。
期間内でも取下げ・不開示等により取得できる保証はない。401/403を保持期間外と推定変換しない。

`--sample-year 2014`は常に負の/歴史経路で、公式原本ZIPを要求しない。
旧2014年raw・manifestは保持し、新しい経路判定を追記する。CUC等の照合は実装しない。

正の照合は、取得した公式ZIPのSHA-256を検査してXBRLを読み、タグと正規化本文が一致した場合のみPASS。
一致したmember名・member hash・要素index・QName・contextRef・比較本文hash・原本schemaを保存する。
監査レコードにはnumad/公式一覧/原本それぞれのmanifest、取得時刻、byte count、提供者版、
API仕様版、safe URL、doc_idへの対応、schema profileを含める。doc_id/URL一致だけではPASSにしない。
