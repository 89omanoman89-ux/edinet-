# Issue #1: P0–P1 minimal acquisition

対象は公式EDINETの日次書類メタデータ1日分と、numad候補アーカイブのJSONL先頭1行。
候補registryは採用認証へ変更しない。P2以降、全市場取得、成績検証は対象外。
標準ライブラリのみで追加依存なし。単一ローカルwriterを前提とする。

## 実装

- `source_acquisition.py`: HTTPSのサイズ上限付き取得、リクエスト間隔、429/5xxと通信失敗の
  bounded retry/backoff、秒数/HTTP-dateのRetry-After、完了リクエストからの再開。
  60秒超の待機要求は`retry_not_before`付きBLOCKED。再実行もその時刻まで取得しない。
- 生バイトはSHA-256名でリポジトリ外へ保存。fsyncした一時ファイルを上書きなしで公開。
  異なるバイトは別ファイル。成功manifestとcheckpointは不変。同じ完了要求の再実行は
  取得時刻を含む同じmanifestを返し、保存バイトのhash/長さも再確認する。
  中断中の未完了転送は最初から再取得する。任意byte offsetからの再開ではない。
- manifestに取得時刻、HTTP結果、safe URL、バイトhash/長さ、doc_id、提供者版、
  API仕様版、利用条件URL、欠損理由を保存。提供者の書類版が不明ならnull。
  日付・type以外のURL queryは要求時に拒否し、資格情報は明示したsecret getterから渡す。
  認証付き通信はredirect禁止。エラー本文・例外本文・任意response headerを保存しない。
- 失敗を削除せず別レコードに残す。空応答、未取得、schema不一致、権利不明は理由付きBLOCKED。
  `docs_checked / file_fetched / schema_profiled / source_tied / rights_reviewed`は独立する。
  docsはレビュー済みバイトhashとの一致が必要。ダウンロードだけではdocs確認へ昇格しない。
- `filing_catalog.py`: EDINET/numadの列型・識別子・件数の検査、元列名とnull理由の保持。
  書類snapshotは原バイトと対応を検査し、日次URL・連番ごとに追加・変更・不在差分を記録する。
  同じdocIDの複数イベントを同一行へ潰さない。
  parentDocID、取下げ、書類情報修正、開示状態を元のまま残し、不在だけから取下げを推定しない。
  同一内容への復帰も新しい取得snapshotとして履歴化する。
- 企業と証券は別表。識別子と名称にvalid/recordedの半開区間と出所を付ける。
  EDINET/法人番号は企業、証券コードは証券へ属する。4/5文字・英字を保持する。
  書類の提出者・発行対象・対象会社は別roleで、同一会社と推定結合しない。
  不明な有効開始日はnullでas-of照合対象外。矛盾する識別子の照合は停止する。
  マスタの保存・検査契約であり、実企業の歴史マスタを構築したという意味ではない。
- `sample_audit.py`: opt-inの実データ統合実行。固定commitから64 KiBをRange取得し、
  完結した先頭JSONL行だけをprofileする。全ファイルのhash/検証と呼ばない。
  原本照合は公式書類APIの取得済みZIPに対する書類ID・XBRLタグ・正規化本文の一致。
  URL/書類IDだけの一致や提供者同士の一致を原本照合へ昇格しない。

## 実行

```sh
python -m unittest discover -s tests -v
python sample_audit.py --private-dir /absolute/private/edinet-issue-1 \
  --snapshot review-20260918 --edinet-date 2026-09-17
```

`--private-dir`はGitリポジトリの外で、私有権限を設定した保存先を指定する。
スクリプトはOSのACLを変更しない。既存Git checkout配下・repository内・解決後のpath escapeを拒否する。
raw、manifest、監査、schema、書類・マスタsnapshot、失敗履歴はすべてここへ保存する。

認証の既定は無効。公式メタデータ/原本経路は`approved_secret_not_configured`を保存する。
ユーザーが承認したsecret管理から環境へ供給済みの場合に限り、設定**名**を
`--edinet-secret-env EDINET_API_KEY`として指定する。値を引数やチャットへ渡さない。
既存`.env`や他の研究領域から探索・転用しない。公開CIでは実行しない。

同じsnapshotは取得済みバイトを再利用する。可変な日次応答や規約を再観測するときは
新しい`--snapshot`を指定する。過去snapshotは上書きしない。候補の変更は別のP0レビューが必要。

## 参照と限界

- [公式API仕様書 Version 2、2026年6月](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/download/ESE140206.pdf)
  に従う。仕様書の例は架空と明記されており実データ証拠に使わない。
- [公式利用規約](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/WZEK0030.html)
  はPDL1.0を参照し、出典表記等を要求する。一般閲覧画面のscrapingで認証不足を迂回しない。
- [numad dataset card（固定版）](https://huggingface.co/datasets/numad/yuho-text-2014-2022/blob/e1dd7e00d5de82aa1b00cf7a28c829d327a93ca7/README.md)
  のlicense表明だけで上流の権利を承認しない。`export_allowed=false`を維持する。

ZIPのXBRLタグ本文一致は限定的な照合方法で、HTMLのみの書類や正規化の差はBLOCKEDになり得る。
取下げ状態の完全なグラフ再構成、歴史マスタ生成、公開権利の法的判定、全書類種別のschemaは未実装。
成功した小標本から全体の取得率・抽出精度を推定しない。
